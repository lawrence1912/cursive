# 体验检查：卡顿与焦点（2026-10-04）

检查基于 `095ed37`，覆盖编辑、查找、标签栏、命令面板、版本历史，以及发布脚本中的表格、图片、公式、源码模式和保存回归。测试使用临时文档和独立的应用支持目录。

## 已确认并修复

| 触发方式 | 原因 | 修复 |
| --- | --- | --- |
| 连续打开两次命令面板，按 Esc | 第二次打开把焦点返回目标覆盖为面板自身的输入框 | 保留首次打开前的焦点，Tab 留在面板内 |
| 正文中打开版本历史 | 浮层没有接管焦点，正文仍接收输入 | 打开时聚焦关闭按钮，Tab 在面板控件间循环，关闭后返回原位置 |
| 从查找框点击已经选中的标签 | 当前标签直接跳过激活，也跳过了编辑器聚焦 | 恢复编辑器焦点，同时保持文档和滚动位置 |
| 长文档开启查找后连续移动光标 | 每次选区变化都重新扫描整份文档计数 | 按正文和查询缓存命中位置，仅更新当前序号；正文或查询变化后重算 |
| 连续输入时每键重建标签栏 | 状态同步无条件重建 DOM，随后读取尺寸触发布局 | 仅标签标题、脏状态、外部冲突、顺序、活动项或语言变化时重建 |

## 测量

macOS 27.0 / arm64，真实 WKWebView，10800 行中文 Markdown（1200 个标题，包含列表与行内格式）。每组连续派发 30 次编辑器事务，计时包含同步更新和 DOM 操作。

| 操作 | 修复前中位数 | 修复后中位数 |
| --- | ---: | ---: |
| 查找无匹配时移动光标 | 11ms | 7ms |
| 查找有匹配时移动光标 | 12ms | 7ms |
| 连续编辑 | 16ms | 14ms |
| 已变脏后连续输入 30 次造成的标签栏重建 | 30 次 | 0 次 |

这些是本机同步事务耗时，不是键盘到屏幕的完整延迟或滚动帧率。少量样本仍超过 16ms，不能据此宣称所有场景都不掉帧。实际中文输入法连续输入仍需人工走查；现有合成事件测试只验证合成期间的装饰稳定性。
