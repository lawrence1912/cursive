# cursive 品牌资产

**主旨：随心所欲，所见即所得。**

## 名字

*cursive* 字面是「草书」——随手连笔写下去，正是"随心所欲"。
而它和 *cursor*（光标）同一个拉丁词根 **currere**（跑）：书写的手在纸上跑，光标在行里跑，
本来就是同一件事。产品那两句话，一个词说完了。

念 /ˈkɜːrsɪv/，两音节。全小写书写，不首字母大写。

## 标志怎么读

标志是**一笔写在纸上的 c** —— cursive 的首字母，也是一笔画到底、没有断过的一条线。

- **整块瓷砖就是那张纸。** 不是白底上摆一张小纸片（那样白压白，什么也看不见），
  是瓷砖本身在当纸：纯白，横格拉满，字直接写在格子上。
- **这一笔是写出来的，不是画出来的。** 入笔细、左侧下行最粗、收笔再提细，末了带一小截
  出锋 —— 硬笔写一个 c 就是这个提按顺序。字身右倾 5°。*cursive* 的意思落在**笔迹**上，
  不靠往图里摆一支笔：笔尖那类道具在 16px 上只会糊成一坨，而且满大街都是。
- **缺口就是光标停的地方。** 写到哪儿，笔就停在哪儿；蓝色那根光标正停在这一笔的末端。
  它是整个标志里唯一的彩色、唯一发光的东西 —— 名字里的那个 cursor，就是它。
  一边是墨、一边是光标，正好是 *cursive* 和 *cursor* 那同一个词根的两副面孔。
- **大尺寸的标志，在 C 的怀里多一行。** 灰色方块是 markdown 标记，因为**光标正停在这一行**
  才显形；后面那节墨色胶囊，是排好版的成品。标记与成品共用同一段文字，是光标决定你此刻
  看见哪一面——这既是"所见即所得"，也正是 cursive 的核心机制：
  *光标移进哪一行，哪一行才回显源码。*
- **应用图标是标志的简化版：纸、这一笔、光标。** 图标真正的工作场合是 16–64px（Dock、
  Finder 列表、⌘Tab），那个尺寸上只有「一笔 c，末端停着光标」立得住；怀里那一行
  32px 起就糊成一团。所以怀里那一行交给 `logo-mark`，从 128px 起才出场。
  横格再小也只是一层极淡的灰，不抢东西，16px 上自然消失。

纸是**纯白瓷砖**：正面是不掺东西的 `#fff`，只在底边落一点点灰，靠一圈内缘发丝线把边
收住；横格是 `#1b2430` 8%，六道，上下各留一道，让这一笔正好落在纸里而不是压出纸外。

**墨的细节有三处**，都不是装饰，是真墨在纸上的样子：

- **洇**：轮廓外描三道极淡的宽边（42/24/11，2%–5%），墨渗进纸纤维的那一圈。
- **积**：落笔处和碗底转向处各压一团暗，笔一慢下来墨就积得深 —— 出锋那头反而不积，
  笔是快着提起来的。
- **色**：墨不是中性灰黑，是偏冷的 `#34353f → #0e1018`，钢笔墨在白纸上就是这个调子。

**瓷砖的形状照抄 macOS。** 1024 的画布里瓷砖占 824、四周留 100；圆角不是普通圆弧，是连续
曲率的超椭圆（`|u/r|^2.6 + |v/r|^2.6 = 1`，r=266）—— 这条路径是逐像素量系统自带图标的遮罩
反推出来的，偏差 ≤1px。这件事有实际后果：macOS 26 会把所有老式 `.icns` 图标往这个形状上
裁一刀，旧版 `rx=185` 的圆角其实一直在被裁；照着遮罩画，才什么都裁不掉。

**图标自己不带落影** —— macOS 26 给图标统一上投影（黑 26%、下移 8、σ=15，也是量出来的），
而且落在遮罩外的东西一律裁掉，自己再烘一层只会是白费或双影。

**手写的这一笔，对上规整的胶囊**：`logo-mark` 里怀抱那一行是几何单线的方块与胶囊 ——
手写的 c 是你敲进去的，规整的胶囊是渲染出来的。字标同理，保持几何单线不跟着写，
表现力交给标记、字标保持中性。这一对不是风格打架，正是产品本身。

试过、没要的：图标里摆一支钢笔尖（32px 变一坨黑，且与所有矢量软件的钢笔工具撞脸）、
白底上摆一张小白纸（白压白，全靠描边撑，小尺寸只剩一团灰）。纸和笔迹留下了，笔这个
道具没留。

## 文件

| 文件 | 用途 |
|---|---|
| `app-icon.svg` | macOS 应用图标 1024，**主版本**（横格纸 + 一笔 c + 光标） |
| `app-icon-dark.svg` | 应用图标，深色瓷砖变体 |
| `logo-mark.svg` | 标志（一笔 c + 怀里那一行），无纸底，浅背景用；**128px 以上才用** |
| `logo-mark-dark.svg` | 标志，无瓷砖底，深背景用 |
| `logo-mark-mono.svg` | 单色，跟随 `currentColor`（印刷、刻印） |
| `logo-lockup.svg` / `-dark` | 应用图标 + 字标横排组合 |
| `wordmark.svg` / `-dark` | 字标单独用 |
| `favicon.svg` | 16–32px 专用简化版（去掉横格，笔画按像素加粗、提按压到最小） |

字标是纯路径的圆头几何单线体，x 高 56、笔画 13、圆头收笔，与图标的胶囊块同一套语言；不依赖任何字体文件。

## 颜色

| 角色 | 值 |
|---|---|
| 纸（瓷砖）· 白 | `#fff` → `#f1f1f3`（只在最后 38% 里落下去） |
| 纸 · 墨（深色变体） | `#3a3a3e` → `#252528` → `#151517` |
| 横格 | `#1b2430` @ 8%（深色变体：白 7%） |
| 内缘发丝线 | 黑 5% → 8% → 13%（深色变体：白 18% → 2%） |
| 墨 | `#34353f` → `#0e1018`（洇 2%–5%，积 42%/26%） |
| 标记块（排好版的那一行） | `#c9c9ce` → `#9a9aa2` |
| 字标 | `#1d1d1f`（深色 `#f5f5f7`） |
| 光标 | `#a8d6ff` → `#3f93f2` → `#0f51ae` |
| 光标辉光 | `#3d90f0` @ 26%（深色变体 34%） |

灰是中性灰，不是暖灰：纯白底上一掺暖色就发脏。

光标蓝与 app 的 `--accent`（`#0969da` / `#6ba6e8`）同族：标志上发光的这一根，
在产品里就是选中、链接和光标的颜色。

## 用法

- **留白**：四周留出不少于图标边长 7% 的空白。
- **最小尺寸**：应用图标 16px（.icns 每一档都从矢量重新栅格，16px 上 C 仍然读得出来）；
  `logo-mark` 128px（怀里那一行再小就糊 —— 那个尺寸是应用图标的活）；组合标志 140px。
  再小请用 `favicon.svg`。
- **别做**：别把光标挪出缺口（**缺口 = 光标位**，挪开语义就没了）、别把 `logo-mark`
  用在 128px 以下、别拉伸、别给图标再加外阴影或描边（投影是系统的活，见上）。

## 重新生成应用图标

矢量源**只有 `brand/app-icon.svg` 一份**。`sips` 直接吃 SVG（渐变、裁剪、透明都保真），
所以不再需要「浏览器打开导出页截图」那一步 —— 旧的 `scripts/icon.html` 已删，它注定与
SVG 对不上。

```
npm run icon      # brand/app-icon.svg → build/icon.png（1024 母版）+ build/icon.icns
```

`.icns` 里每一档尺寸都是**从矢量重新栅格**的（不是把 1024 缩下去），16/32px 才不糊。

一个坑：**`sips` 不认 `feGaussianBlur`** —— 写了它不报错，直接当没有，糊出来是一道硬边。
所以图标里没有一处用滤镜：墨洇是给轮廓描三道宽边（一半压在墨下、一半渗到纸上），墨积是
裁在笔画里的径向渐变。都是纯几何，sips、浏览器、任何别的渲染器出来一模一样。

那一笔的外轮廓是**变宽度笔画拟合出来的三次贝塞尔**（椭圆中线 + 提按宽度函数 → 逐段拟合，
偏差 ≤1.1px，全笔 1.1KB），不是几百个点的折线 —— 这样文件还改得动。右倾 5° 已经烘进
坐标，省掉一层 `transform`。
